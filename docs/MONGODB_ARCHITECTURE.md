# Trace — MongoDB Architecture

Trace uses MongoDB as the **analytical serving layer** for the RetailRocket dashboard. The default deployment (**compact mode**) stores pre-aggregated rollups suitable for **MongoDB Atlas M0 (512 MB)**. The **full processed dataset** remains on disk under `data/processed/` and is never replaced by MongoDB document counts.

## End-to-end flow (compact — default)

```text
Raw CSV (data/raw/) — immutable
        ↓
Python processing (process_dataset.py)
        ↓
Processed CSV + JSON summaries (data/processed/) — authoritative counts
        ↓
Offline rollups (build_mongodb_rollups.py) — 100% of events streamed
        ↓
Rollup artifacts (data/mongodb_free_tier/)
        ↓
Compact import (import_analytics_to_mongodb.py)
        ↓
MongoDB compact collections (retailrocket_analytics)
        ↓
FastAPI reads rollups / targeted aggregations
        ↓
Trace dashboard (React)
```

## Why not store full `events` and `item_properties` in Atlas Free?

| Factor | Full import | Compact rollups |
|--------|-------------|-----------------|
| Events | ~2.76M documents | 0 (aggregated offline) |
| Item properties | ~20.3M EAV rows | 0 (latest metadata only for event products) |
| Storage | Far above 512 MB | Designed to stay under M0 limit |
| Analytics | `$group` on raw events | Read `analytics_global`, `product_metrics`, time series |

Academic interpretation: this is **materialized aggregation** / **OLAP-style summary tables** in a document store— the warehouse facts stay in the **local processed files**; MongoDB holds **derived analytical projections** for low-latency API serving.

## Compact collections (Atlas Free tier)

| Collection | Documents (approx.) | Role |
|------------|---------------------|------|
| `analytics_global` | **1** | Overview, funnel, behavior, report peaks — single document |
| `product_metrics` | ~235K | Per-product views, add-to-cart, transactions |
| `product_metadata` | ≤235K | Latest `categoryid` and `available` per event product |
| `time_series_daily` | ~120 | Daily views/addtocart/transactions/total_events |
| `time_series_hourly` | ~2.8K | Hourly buckets (date + hour UTC) |
| `category_tree` | 1,669 | `categoryid`, `parentid` |

**Not imported in compact mode:** `events`, `item_properties`.

### `analytics_global` (single document)

Nested sections mirror API needs:

- `overview` — KPIs, event distribution, date range, visitor conversion  
- `funnel` — unique visitor counts at view / addtocart / transaction stages  
- `behavior` — summary, activity buckets, top 15 visitors, engagement metrics  
- `report_meta` — peak activity day, peak transaction day, peak hour (UTC)

### `product_metrics`

| Field | Meaning |
|-------|---------|
| `item_id` | Product identifier |
| `views` | View event count |
| `add_to_cart` | Add-to-cart event count |
| `transactions` | Transaction line-item count |

### `product_metadata`

| Field | Meaning |
|-------|---------|
| `item_id` | Product in event set |
| `properties.categoryid` / `properties.available` | Latest value by timestamp from streamed `item_properties.csv` |

### Time series collections

Daily: `date`, `views`, `addtocart`, `transactions`, `total_events`  
Hourly: `date`, `hour`, same metrics.

## Rollup artifacts (`data/mongodb_free_tier/`)

Generated by `scripts/build_mongodb_rollups.py` (does not modify processed CSVs):

- `analytics_global.json`
- `product_metrics.jsonl`, `product_metadata.jsonl`
- `time_series_daily.jsonl`, `time_series_hourly.jsonl`
- `category_tree.jsonl`
- `rollup_manifest.json`, `rollup_validation.json`
- `analytics_import_report.json` (after import)

## Compact import strategy

Script: `scripts/import_analytics_to_mongodb.py`

1. Ping MongoDB.  
2. Require rollup artifacts (or run builder first).  
3. With `--drop`, drop **only** compact collections listed above — never `events` / `item_properties`.  
4. Batch insert from JSON/JSONL.  
5. Create **minimal** indexes (see below).  
6. Write import report with document counts.

## Index strategy (compact)

| Collection | Indexes | Notes |
|------------|---------|--------|
| `analytics_global` | *(none)* | Single document |
| `product_metrics` | unique `item_id`; optional sort on views / add_to_cart / transactions | Rankings use `$sort` + `$limit` |
| `product_metadata` | unique `item_id` | Product detail lookup |
| `time_series_daily` | `date` | Date-range filters |
| `time_series_hourly` | unique `(date, hour)` | Hourly series |
| `category_tree` | unique `categoryid` | Hierarchy lookup |

Avoid extra indexes on M0 to preserve headroom under 512 MB.

## Legacy full-storage mode (local MongoDB only)

For unlimited local storage, `scripts/import_to_mongodb.py` can still import:

- `events` (~2.76M)  
- `item_properties` (~20.3M)  
- `category_tree`

The current FastAPI backend is wired for **compact** collections only. Full import is retained for academic comparison or self-hosted MongoDB with sufficient disk; it is **not** used for Atlas Free tier.

## Operational notes

- Build rollups: `python scripts/build_mongodb_rollups.py`  
- Import compact analytics: `python scripts/import_analytics_to_mongodb.py --drop`  
- Credentials only in `.env` (not committed).
